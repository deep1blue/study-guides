SFT Mechanics: Teaching the Model Its Manners

September 28, 2026 · Interview-prep series

Supervised fine-tuning is the step that turns a next-token predictor into an instruction follower. The loss function barely changes from pretraining — the masking decision is the whole trick. This guide goes intuition → mechanism → math, with the failure modes interviewers actually probe.

1Why SFT exists

A base (pretrained) model computes P(next token | previous tokens) over raw internet text. It is a document-completer, not an assistant. Prompt it with Q: write a haiku about GPUs / A: and it may emit three more questions — because on the internet, a Q/A list continuing with more Q/A pairs is a perfectly plausible continuation. The model has no notion of "you are being asked to do something." SFT installs that notion.

Figure 1 — Same prompt, different training. Pretraining built the knowledge; SFT elicits the assistant persona.

One-line version: SFT converts P(next text) into P(response | instruction). Pretraining is raising a brilliant kid with no manners; SFT is the short, careful schooling.

📄 Deep dive — the papers

  • Training language models to follow instructions with human feedback (Ouyang et al., 2022) — the InstructGPT paper; SFT as step one of the alignment pipeline.
  • LIMA: Less Is More for Alignment (Zhou et al., 2023) — 1,000 curated examples align a 65B model; the Superficial Alignment Hypothesis.
  • The False Promise of Imitating Proprietary LLMs (Gudibande et al., 2023) — why imitation-style SFT data can fool benchmarks while missing capability.

2Chat templates — the silent killer

Roles are wrapped in special tokens. The model only ever learns the exact token format it trained on. Train with template A, serve with template B → no error, no crash, just degraded answers. Weeks of work lost to a string-format mismatch.

Figure 2 — Token layout of one SFT example. Training and inference templates must match token-for-token.

📄 Deep dive — templates in practice

  • Hugging Face: Chat templating — how apply_chat_template works and why mismatches bite.
  • TRL: SFTTrainer documentation — the standard SFT loop, masking, and packing options.

3Loss masking — the whole trick

Standard causal-LM training: labels = input ids shifted left by one, cross-entropy over all positions. For SFT we set every prompt (user/system) token's label to −100, which is CrossEntropyLoss's ignore_index — those positions contribute zero loss and zero gradient.

Figure 3 — Masked labels. Prompt positions are −100 (ignore_index): no loss, no gradient. Only assistant-response tokens teach.

Multi-turn masking

Conversation: user, assistant, user, assistant. Every assistant turn gets loss; user and system turns get −100. An off-by-one in masking code trains on the wrong half of the conversation — silently, since the loss still decreases.

4The math that matters

Masked cross-entropy, with Nresp = number of response tokens:

L = −(1/Nresp) · Σt ∈ response log p(xt | x<t)

Same loss as pretraining, restricted to response tokens. Masking converts "predict the joint P(x₁…xT)" into behavior cloning: a product over turns of P(assistant_turn | conversation so far).

Subtlety interviewers love: the loss averages over response tokens only, so wildly varying response lengths change the effective gradient mix per batch. Watch token count, not example count, when reasoning about effective batch size. This is also why packing examples without attention boundaries leaks — the model learns spurious cross-example dependencies.

5Training regime

1–3 epochs, learning rate ~1–2e−5, often via LoRA/QLoRA. You are nudging settled weights, not rebuilding them. More epochs or a higher LR → catastrophic forgetting: the narrow SFT distribution overwrites broad pretraining knowledge.

📄 Deep dive — what SFT can and can't do

  • LIMA (Zhou et al., 2023) — the Superficial Alignment Hypothesis: alignment is mostly about eliciting the right format/behavior, which pretraining already contains.
  • The False Promise of Imitating Proprietary LLMs — imitation data improves style metrics while leaving capability gaps; a cautionary tale for scraped SFT datasets.

6The 8 gotchas — know the why

1. Chat-template mismatch. The model learned one exact token format. Serve another and quality degrades with no error — silent, and it wastes weeks.
2. Forgetting prompt loss masking. You train P(user tokens) too — the model roleplays the human instead of answering.
3. Masking the wrong turns in multi-turn. Off-by-one trains on the wrong half of the conversation, silently.
4. Too many epochs / too high LR. Catastrophic forgetting: the narrow SFT distribution overwrites pretraining knowledge.
5. Junk data at scale. SFT teaches behavior — 500k scraped pairs teach confident wrongness and style quirks.
6. Benchmark contamination. Eval questions in training data → inflated scores, false confidence, wasted iteration.
7. Packing without attention boundaries. Examples attend across boundaries; the model learns spurious cross-example dependencies.
8. Style / sycophancy overfitting. SFT rewards the shape of good answers (annotators preferred thorough, agreeable responses) → verbosity and sycophancy. This is exactly what the RL stage exists to fix.

7Connection to RLHF — the Staff-level link

The SFT model becomes πref in PPO. The KL penalty β·KL(π ‖ πref) anchors the RL policy to this model. A sloppy SFT — contaminated, style-overfit, template-broken — poisons everything downstream. SFT quality is RLHF quality.

Figure 4 — The alignment pipeline. SFT's output is RLHF's anchor: sloppy SFT poisons everything downstream.

📄 Deep dive — the RLHF papers

  • Fine-Tuning Language Models from Human Preferences (Ziegler et al., 2019) — the original RLHF recipe: SFT → reward model → PPO.
  • Proximal Policy Optimization Algorithms (Schulman et al., 2017) — PPO, the RL workhorse with the KL constraint.
  • Direct Preference Optimization (Rafailov et al., 2023) — the RL-free alternative; still starts from the SFT policy as π_ref.

8Self-test

Cover the answers. Say each one aloud until it's clean.

1. Base model writes more questions instead of a haiku. Why?

It models P(next text), not P(helpful response). On the internet, Q/A lists continuing with more questions are plausible continuations. No notion of instruction-following.

2. What does −100 do inside the loss, mechanically?

It's ignore_index in CrossEntropyLoss: those positions contribute zero loss and zero gradient.

3. Multi-turn: which tokens get loss? What breaks with an off-by-one?

All assistant turns get loss; user/system turns are −100. An off-by-one trains on the wrong half of the conversation — silently, since loss still decreases.

4. Template A at train, template B at serve. Failure mode? Why "silent"?

The model only knows the exact token format it trained on. No error, no crash — just degraded answers. Weeks wasted on a string mismatch.

5. Teammate says "add 500k more SFT examples to be safe." Your call?

Push back. SFT teaches behavior/format, not knowledge — quality dominates quantity (LIMA). 500k scraped examples risk contamination and style overfitting. 1–3 epochs, small LR.

6. SFT'd support model now refuses benign questions and answers 3× longer. Diagnose?

Two failure modes. Over-refusal: refusal-heavy data mix taught "refuse when uncertain" — verify with a held-out over-refusal benchmark, compare refusal rates pre/post SFT. Verbosity: style overfitting (gotcha #8) — verify via length-distribution shift and length-controlled evals. Fix: rebalance with compliant near-boundary examples, length-diverse data, cap epochs/LR, length-penalized RLHF next.

7. Why does the SFT model become π_ref, and why does that make SFT quality downstream-critical?

The KL penalty β·KL(π ‖ π_ref) anchors the RL policy to the SFT model. Sloppy SFT poisons RLHF.

8. Response lengths vary 10× in your SFT batch. What breaks, and what do you monitor instead?

Loss averages over response tokens only, so the effective gradient mix skews toward long responses. Monitor token count, not example count, for effective batch size.

🎯 Your 30-second interview answer

"SFT converts a next-token predictor into an instruction follower by fine-tuning on instruction–response pairs with loss computed only on the response tokens. The LIMA result — a thousand curated examples aligning a 65B model — shows SFT teaches format and behavior, not new knowledge."
