Arrays: The Foundation

September 28, 2026 · Interview-prep series

The array is the trunk of the whole algorithms track: a contiguous block of fixed-size slots where position is arithmetic. This guide derives the cost table from that one fact, proves amortized O(1) append via the doubling series, and installs the two load-bearing techniques — in-place read/write pointers and prefix sums.

1Builds on

L7 — Big-O, Ω, Θ. The exact idea reused: the growth-rate vocabulary. Every cost below is stated as a function of n and you're expected to read it fluently. L1 itself is the trunk: it has no prerequisites on the tree, but nothing after it floats alone.

The intuition: a row of wooden cubby-holes, shoulder to shoulder, numbered 0, 1, 2, … with one rule — every cubby is the same size and there are no gaps. Want the card in cubby 4,217? You don't walk past 4,217 cubbies; you multiply: start of the row plus 4,217 × cubby width. One multiplication, one jump. That is the entire array — and both halves of its bargain.

2Address arithmetic — why indexing is Θ(1)

Figure 1 — Same-size slots, zero gaps: position is arithmetic. Insert into slot 3 and every card after it must physically slide — the contiguity tax.

Same-size elements plus zero gaps means base + i × w is a constant number of operations for any i. That's the derivation of Θ(1) indexing — not "fast," but literally independent of n. The flip side: inserting at position k shifts n − k elements, each a constant-time move, so insertion/deletion at k costs Θ(n − k), worst-case Θ(n) at the front.

The hardware angle (why this matters beyond interviews): contiguous data is what silicon loves. Sequential slots prefetch cleanly, vectorize under SIMD, and coalesce on GPUs — the same reason tensors want to be contiguous. When an interviewer asks why something is fast "in practice," cache locality from contiguity is usually half the answer.

3The doubling trick — amortized O(1) append, derived

A Python list is a dynamic array: fixed capacity underneath; when an append overflows it, the runtime allocates a geometrically larger block (about 9/8× in CPython — the exact factor never matters, only that it's geometric) and copies everything over. Copying n elements looks like O(n) per append. Count the total work of n appends instead:

Figure 2 — Geometric resizing: the copy costs form a convergent series, so the average append stays constant. Full treatment at L10 (amortized analysis).

The key insight: any growth factor strictly above 1 gives a convergent geometric series — that's why the proof doesn't care whether it's 2× or 9/8×. Expensive moments exist (the occasional full copy), but averaged over the sequence, append is O(1). Every dynamic array in every language leans on this one series.

4In-place read/write pointers — the seed of L13

Canonical problem: remove duplicates from a sorted array, in place. Sorted means duplicates sit adjacent, so one scan with two pointers does it: read visits every element; write marks where the next unique value belongs.

Figure 3 — The read/write pattern. Compare each element to its predecessor; only uniques advance the write head. Θ(n) time, O(1) space.
# Sorted array -> duplicates are adjacent. Two pointers:
# `read` scans every element; `write` marks where the next
# unique value belongs. Time Theta(n), space O(1).
def remove_duplicates_sorted(nums):
    if not nums:
        return 0
    write = 1
    for read in range(1, len(nums)):
        if nums[read] != nums[read - 1]:
            nums[write] = nums[read]
            write += 1
    return write  # length of the deduped prefix

The comparison must be against nums[read - 1] — the previous element — not nums[write]. The write head lags behind read, so comparing to it skips values. State the invariant aloud in the interview ("nums[0..write] is always the deduped prefix") and this whole pattern family — L13 two pointers, L17 in-place transforms — opens up.

5Prefix sums — O(n) once, O(1) per query

Canonical problem: many range-sum queries on a static array. Precompute P[i] = sum(nums[0..i-1]) with P[0] = 0; then sum(nums[l..r]) = P[r+1] − P[l] in O(1). The word "many queries" in a prompt is the prefix-sum tell — you're buying O(1) answers with one O(n) preprocessing pass.

Figure 4 — One O(n) pass builds P; every query is a subtraction. Same idea powers L16 (prefix sums) and L36 (DP tables).
# Precompute P where P[i] = sum(nums[0..i-1]); P[0] = 0.
# Build O(n) once, answer each query O(1).
class RangeSum:
    def __init__(self, nums):
        self.prefix = [0]
        for x in nums:
            self.prefix.append(self.prefix[-1] + x)

    def query(self, left, right):  # inclusive bounds
        return self.prefix[right + 1] - self.prefix[left]

6The 7 gotchas — Python edition

1. Silent negative-index wrap. a[i-1] with i = 0 doesn't crash — it reads the last element. The most expensive array bug is the one that doesn't raise.
2. Empty / single-element arrays. Guard if not nums before any loop touching a[i-1]; interviewers test the boundaries first.
3. Mutating while iterating. Removing inside for x in a skips elements — indices shift under your feet. Iterate a copy or build a new list.
4. pop(0) / insert(0, x) are O(n). Every remaining element shifts. Hot ends mean deque (L4), not list.
5. Slicing copies. a[i:j] is Θ(j−i); inside a loop it's a hidden quadratic — the L7 trap in an array costume.
6. Aliasing. b = a shares storage; [[]] * n shares one inner list n times. Copy deliberately with a[:].
7. Value vs. index. n is the size, not the max value — "loop to n" is O(n); "loop over digits of n" is O(log n). (L7 pitfall, still biting.)

7Connects to — what L1 unlocks

Everything below is one of three moves: use the array, extend the array, or escape the array's weakness:

  • L2 — Strings: arrays of characters, with encoding gotchas on top.
  • L5 — Hash maps: arrays plus a hash function: O(1) by value instead of by position.
  • L13 — Two pointers: today's read/write pattern grows up.
  • L16 — Prefix sums: today's second technique, its own lesson.
  • L18 — Binary search: only works because arrays give O(1) mid access.
  • L24+ — Trees: a binary heap is an array in disguise (children of i at 2i+1, 2i+2).
  • L36 — DP: the DP table is an array.

8Self-test

Cover the answers. Say each one aloud until it's clean.

1. Why is a[i] Θ(1) but inserting at position k Θ(n−k)?

Indexing is address arithmetic — base + i × w, constant work for any i. Insertion at k must shift the n − k elements after k, each a constant-time move. Same contiguity, two consequences.

2. n appends to a dynamic array: total work, and why?

Under 3n. Copies happen at sizes 1, 2, 4, …, 2m (2m < n) and sum to less than 2n; plus n cheap appends. So each append is O(1) amortized.

3. CPython grows lists ~9/8×. Why doesn't the exact factor matter for the proof?

Any factor strictly above 1 makes the copy costs a convergent geometric series — total copies stay linear in n. The proof only needs "geometric," not a specific number.

4. In remove-duplicates, what breaks if you compare nums[read] != nums[write]?

The write head lags behind read, so comparing to it skips values that should be kept. Compare against the previous element, nums[read − 1] — sorted order makes duplicates adjacent.

5. a = [1,2,3]; b = a; b[0] = 9. What is a[0], and why?

9. b = a copies the reference, not the storage — both names point at the same array. Copy deliberately with a[:] or list(a).

6. pop(0) inside a loop over n elements: total cost, and the fix?

O(n²) — each pop(0) shifts n−1 elements. Use collections.deque (L4) for O(1) pops from the left.

7. Why is the prefix-sum query P[r+1] − P[l], not P[r] − P[l]?

Because P[i] is defined as the sum of the first i elements. P[r+1] covers nums[0..r]; subtracting P[l] removes nums[0..l−1], leaving nums[l..r]. The +1 offsets are the whole trick — draw the fence posts.

8. Sorted array, "find a pair summing to target." Two pointers or hash map — and why?

Two pointers: left at 0, right at n−1; move inward based on whether the sum is too small or too big. Θ(n) time, O(1) space — it exploits sortedness, which the hash map ignores. The hash map also works (Θ(n)/Θ(n)) but wastes the order information; on a sorted array, name the two-pointer solution first.

🎯 Your 30-second interview answer

"An array is a contiguous block of fixed-size elements, so an index is arithmetic — base plus i times element size — which is why access is Θ(1). The same contiguity makes insertion or deletion at position k cost Θ(n−k), because everything after it shifts. Python lists are dynamic arrays: append is O(1) amortized, since geometric resizing means n appends do under 3n total work. The two load-bearing techniques are read/write pointers for in-place transforms and prefix sums for O(1) range queries. Everything else in the track is either an array, an array with extras, or something invented because arrays can't do one thing."
