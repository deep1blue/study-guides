Strings: The Array's Tricky Sibling

September 29, 2026 · Interview-prep series

A Python string is an immutable array of Unicode code points. L1's contiguity bargain carries over unchanged — Θ(1) indexing — but immutability turns every "edit" into a rebuild. Price the rebuilds (the += loop hides a Θ(n²)), then let symmetry do the work: converging two pointers and expand-around-center.

1Builds on L1 — and one new rule

L1's contiguity bargain is the whole foundation: position is arithmetic (address = base + i × w), so s[i] is Θ(1); the middle is expensive because everything after it shifts. A string inherits this table line for line. The new rule is immutability: you cannot change any bead on the cord. So even the end costs Θ(n) to "edit" — s + "x" copies all of s. Three consequences to lock in:

  • Every string "edit" is a rebuild. s[:i] + new + s[i+1:] makes three fresh copies.
  • Immutability is a feature, not a bug: strings are hashable (dict keys — L5 needs this) and thread-safe.
  • "In-place" string problems (LC 344, reverse string) mean: convert to a list, do the pointer dance, "".join at the end.

A "character" is three layers. The grapheme is what a human sees (one letter, one emoji). The code point is the Unicode number — and it is what Python counts. The bytes are the UTF-8 encoding, one to four bytes per code point:

2The math: the restring tax, derived

Derivation 1 — s += c in a loop. The k-th append copies the whole k−1-character string plus the new char: k units of work. Total over n appends:

1 + 2 + … + n = n(n+1)/2 = Θ(n²)

With "".join(parts): a list of parts holds Θ(n) characters total, then one pass writes each character once: Θ(n). For n = 10,000, the += loop does roughly 50 million character copies; join does 10,000. Same output, 5,000× less work.

Figure 2 — Schlemiel the Painter: each append repaints the whole wall. join paints once.

Derivation 2 — expand-around-center vs brute force. There are Θ(n²) substrings and each palindrome check costs O(n): brute force is Θ(n³). Every palindrome has a center, and there are 2n−1 of them (n characters + n−1 gaps between characters). Expanding from each center costs O(n):

2n−1 centers × O(n) expansion = O(n²) time, O(1) extra space

One whole order of magnitude bought by symmetry alone. (Manacher's O(n) algorithm exists and is baroque — interviewers don't expect it. Know its name, not its code.)

3The code: symmetry does the work

Problem 1 — Valid Palindrome (LC 125). L1's read pointers, now walking from both ends toward the middle — the seed of L13 (two pointers):

def is_palindrome(s):
    # Two pointers converge from both ends.
    # Invariant: everything outside [left, right] has been checked
    # and matched. Each char visited at most once -> Theta(n), O(1) space.
    left, right = 0, len(s) - 1
    while left < right:
        if not s[left].isalnum():   # skip the noise
            left += 1
            continue
        if not s[right].isalnum():
            right -= 1
            continue
        if s[left].lower() != s[right].lower():
            return False
        left += 1
        right -= 1
    return True
Figure 3 — Converging pointers. The palindrome's symmetry means you only ever walk inward.

Problem 2 — Longest Palindromic Substring (LC 5). Expand around the center instead of enumerating substrings:

def longest_palindrome(s):
    # Every palindrome has a center: 2n-1 of them
    # (n chars + n-1 gaps). Expand from each as far as the
    # symmetry holds; keep the longest. 2n-1 x O(n) = O(n^2), O(1) space.
    def expand(l, r):
        while l >= 0 and r < len(s) and s[l] == s[r]:
            l -= 1
            r += 1
        return r - l - 1  # span of the found palindrome

    start, best = 0, 0
    for i in range(len(s)):
        length = max(expand(i, i),      # odd: center on char i
                     expand(i, i + 1))  # even: center between i, i+1
        if length > best:
            best = length
            start = i - (length - 1) // 2
    return s[start:start + best]
Figure 4 — One odd center expanding. Even centers live between characters; both kinds get tried.

4How to spot it: the string tells

  • "Palindrome" → symmetric two pointers (check) or expand-around-center (longest).
  • "Anagram" → count characters, don't compare strings (L5/L6 seeds).
  • "Longest/shortest substring" with a property → sliding window (L14).
  • Building a string piece by piece → collect parts, "".join once. The += trap is the #1 string performance question.
  • "In-place" on a string → list of chars, pointer dance, "".join.
  • "Encode and decode" → design the delimiter/escaping yourself (LC 271, the classic follow-up).

5The 7 gotchas — know the why

1. += in a loop is Θ(n²). Each append restrings the cord. Collect in a list, join once — and say the Σk derivation out loud.
2. String methods return new strings. s.lower() alone does nothing; you must reassign. The mutation never happens — that is immutability, and it bites exactly once.
3. Slicing copies. s[i:j] is Θ(j−i); inside a loop over n positions it's a hidden quadratic — the L7 trap in a string costume.
4. Negative-index wrap. s[-1] is the last char, not an error. A two-pointer that overshoots wraps silently to the wrong end.
5. Normalization first. "A man, a plan, a canal: Panama" only palindromes after lowercasing and stripping non-alphanumerics. Decide where the cleaning lives — inline or up front.
6. Off-by-one in expand-around-center. 2n−1 centers, not n; even palindromes live between characters. The span formula r - l - 1 falls out of where the failing indices land.
7. len() counts code points, not graphemes. One visible character can be several code points. Interviews assume ASCII; production remembers the three layers.

7Self-test

Cover the answers. Say each one aloud until it's clean.

1. Derive the cost of s += c in a loop from scratch.

The k-th append copies k−1 old chars plus the new one: k units of work. Total = 1 + 2 + … + n = n(n+1)/2 = Θ(n²). Name it: Schlemiel the Painter.

2. What does "".join(parts) change about that math?

The list holds Θ(n) characters total; join does one allocation and one pass, writing each char once: Θ(n). The copies per iteration disappear because there are no iterations of rebuilding.

3. len("café👨‍👩‍👧") — and what does it not count?

9 — it counts code points (4 for "café", 5 for the family emoji), not the 5 graphemes a human sees, and not the 25 UTF-8 bytes on the wire.

4. Expand-around-center: why 2n−1 centers and not n?

Odd palindromes center on a character (n of them); even palindromes center between two characters (n−1 gaps). Skip the even centers and you miss "abba".

5. In is_palindrome, the pointers cross with no mismatch. Return value, and why?

True. The invariant: everything outside [left, right] matched. Crossing means nothing is left unchecked — all pairs matched.

6. s == s[::-1] also checks palindromes. Why might an interviewer want the two-pointer version?

The slice is Θ(n) extra space plus a full copy; two pointers are O(1) space and can short-circuit on the first mismatch. Know both; lead with trade-offs.

7. Brute-force longest palindrome is Θ(n³) — where does each factor come from?

Θ(n²) substrings (n choices of start × O(n) choices of end) times an O(n) palindrome check per substring. Expand-around-center kills the middle factor: 2n−1 centers × O(n) expansion.

8. You have 10,000 strings and need all with a given prefix. Why is a trie (L31) better than scanning?

Scanning compares the prefix against every string: O(total length). A trie shares common prefixes, so each query costs O(prefix length) regardless of how many strings you stored.

🎯 Your 30-second interview answer

"A Python string is an immutable array of Unicode code points — same Θ(1) indexing as an array from the contiguity bargain, but every edit is a rebuild, so appending in a loop is Θ(n²) while collecting parts and calling join once is Θ(n). The two load-bearing patterns are two pointers converging from both ends for symmetry problems like palindromes — Θ(n) time, O(1) space — and expand-around-center for the longest palindromic substring: 2n−1 centers at O(n) each is O(n²) time in O(1) space, a full order better than brute force's O(n³). The whole string lesson: treat them as arrays, respect immutability, and let symmetry do the work."
